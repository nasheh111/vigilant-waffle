# AIGC 商品宣传图自动出图 Agent - 面试问答版

## 参考项目名称

- 电商商品宣传图智能生成平台
- 商品宣传图自动出图 Agent
- 智能商品图工厂

## 一句话介绍

这是一个面向电商运营的商品宣传图自动出图 Agent。运营只需要上传商品信息、商品主图和投放尺寸，系统就能自动完成卖点提炼、创意策划、商品抠图、背景生成、文案排版、多尺寸适配和质检自愈，最终交付 3-5 张可选宣传图。

我在项目里重点负责 Agent 流程设计、Prompt 结构化输出、素材/模板检索、合规校验和质检自愈链路，让系统不是单纯“画一张图”，而是能稳定地产出符合平台规范的电商物料。

## 面试官：这个项目是解决什么问题的？

回答口径：

这个项目主要解决电商出图的三个问题：效率、合规和风格一致性。

传统流程里，运营要先整理商品卖点，再找设计做图，还要适配主图、详情页、推广图等多个尺寸。一个 SKU 如果要做多平台投放，改图成本很高，而且容易出现广告法违禁词、价格写错、文字越界、品牌风格不一致这些问题。

所以我把它设计成一个自动出图 Agent。用户输入商品信息和商品图后，系统先结构化商品卖点，再规划视觉方案，然后做商品主体处理、背景生成、文案排版、多尺寸适配，最后由质检 Agent 做合规和视觉检查。不通过时不会整图重跑，而是定位到具体环节定向修复。

## 面试官：你具体是怎么做的？

回答口径：

我把整个链路拆成 6 个核心节点：

1. 输入预处理：解析商品名称、品类、卖点、价格、目标人群、平台尺寸等字段。
2. 卖点提炼：用 LLM 把运营输入的长文本转成结构化 JSON，比如核心卖点、适用场景、禁用词风险、主标题候选。
3. 创意策划：根据商品类目、节日、品牌调性，从模板库和优秀案例库中检索相似风格，再生成构图方案。
4. 画面生成：先做商品主体分割和抠图，再生成或检索背景素材，最后做商品与背景融合。
5. 文案排版：根据平台尺寸和安全区规则，把主标题、副标题、卖点标签、价格信息渲染到图上。
6. 质检自愈：检查广告合规、文案事实一致性、视觉质量、尺寸规范，不通过就回到责任节点重做。

这里我比较强调两点：第一，所有 LLM 输出都尽量结构化，用 JSON Schema 约束字段，方便后续节点消费；第二，低质量结果不直接交付，而是由质检结果驱动定向返工。

## 面试官：为什么要用 Agent，而不是直接调文生图模型？

回答口径：

因为电商宣传图不是单纯的图片生成任务，它有很多业务约束。

比如商品卖点不能写错，价格不能写错，不能出现广告法违禁词，主图文字不能超安全区，不同平台尺寸要适配，同一个品牌的视觉风格还要统一。如果只是直接把一句 Prompt 丢给文生图模型，生成结果不可控，后处理成本反而很高。

所以我用 Agent 的方式，把复杂任务拆成多个可控节点：卖点提炼负责理解商品，创意策划负责方案，画面生成负责视觉，排版负责平台规范，质检负责把关。每个节点都有输入输出边界，失败了也能定位是哪一步的问题。

## 面试官：系统整体架构是什么？

回答口径：

整体可以分成四层：

1. 接入层：运营工作台，负责上传商品信息、商品图、尺寸要求，查看生成进度和下载结果。
2. Agent 编排层：负责串联卖点提炼、创意策划、画面生成、文案排版、质检自愈等节点。
3. 模型与工具层：包括 LLM、商品分割模型、文生图/图生图模型、OCR/规则校验、图片合成和压缩工具。
4. 资产与知识层：包括商品主体库、品牌资产库、风格模板库、场景素材库、广告法/平台规则知识库。

流程上是：用户输入 -> 商品信息结构化 -> 模板/规则检索 -> 创意方案生成 -> 商品抠图和背景生成 -> 文案排版 -> 多尺寸适配 -> 质检 -> 交付。

## 面试官：知识库/RAG 在这个项目里怎么用？

回答口径：

RAG 主要用在三类场景。

第一类是合规知识，比如广告法违禁词、平台主图规范、类目宣传限制。生成前先检索相关规则，避免 Prompt 阶段就写出高风险文案；生成后再回查一次，做二次校验。

第二类是优秀案例和模板检索。不同品类适合的画面风格不一样，比如美妆更强调质感，食品更强调食欲感，数码更强调参数和科技感。系统会按商品类目、风格标签、节日场景检索相似案例，作为创意策划参考。

第三类是品牌资产检索，比如品牌色、Logo、字体、历史投放模板。这样同一个品牌多次出图时，视觉不会每次都漂。

## 面试官：你怎么保证生成的宣传图合规？

回答口径：

我做的是“双阶段合规校验”。

第一阶段在创意策划前后做预检。系统会检索广告法条款和平台规则，对标题、卖点、促销词做违禁词和夸大宣传检查，比如“最”“第一”“国家级”“永久有效”等词会被标记。

第二阶段在成图质检时复核。因为有些风险不是文字阶段能完全发现的，比如价格和商品信息不一致、文案区域超安全区、平台尺寸不符合要求。所以质检节点会重新检查文案、尺寸、格式、文字占比和安全区。

如果只是文案违规，就只回到文案节点重写；如果是排版越界，就只回到排版节点调整；如果是主体融合不自然，就回到融合节点处理。

## 面试官：多尺寸适配怎么做？

回答口径：

我没有把多尺寸适配理解成简单裁剪，因为简单裁剪很容易把商品主体或文字裁掉。

我的做法是先抽象出一份版式描述，包括商品主体位置、文案区、安全区、背景延展区域和视觉重心。生成 800x800 主图后，再根据不同平台尺寸重新计算布局，比如详情页长图、推广横图、社媒方图，它们共享同一套创意和素材，但版式会重新排布。

背景可以延展或重新生成，商品主体和核心文案保持一致，最后再做尺寸、格式、压缩和清晰度检查。

## 面试官：质检自愈具体怎么做？

回答口径：

我把质检拆成四类指标：

1. 文案一致性：商品名称、卖点、价格、促销信息是否和输入一致。
2. 合规性：是否命中广告法违禁词、平台限制词、夸大宣传。
3. 视觉质量：主体边缘是否毛糙、光影是否一致、文字是否清晰可读。
4. 平台规范：尺寸、格式、文字占比、安全区是否符合要求。

质检结果不是只给一个通过/不通过，而是返回结构化错误，比如 `copy_risk`、`layout_overflow`、`bad_cutout`、`brand_mismatch`。编排层根据错误类型把任务路由回对应节点，最多重试 3 次，超过就转人工审核。

## 面试官：这个项目里最大的难点是什么？

回答口径：

最大的难点是“可控性”。图片生成模型本身有随机性，但电商业务要求结果稳定、合规、可复用。

我主要从三方面控制：

第一，输入输出结构化。卖点、风格、版式、质检结果都用结构化字段承接，减少自然语言在节点之间传递造成的歧义。

第二，资产复用。商品主体、品牌资产、场景素材和模板都入库，命中已有素材时优先复用，减少每次都重新生成导致的风格漂移。

第三，质检闭环。把低质量结果拦在交付前，并且定向返工，不让系统无限重试或乱改。

## 面试官：你怎么降低成本？

回答口径：

主要靠三点。

第一是缓存和资产复用。同一个 SKU 的商品主体图、品牌资产和历史模板会入库，下次出图不再重复抠图和生成背景。

第二是模型分级。简单任务用轻量模型，比如卖点提炼、违禁词检查、模板匹配；只有背景生成、精修这种高价值环节才调用成本更高的图像模型。

第三是定向返工。质检失败时只重做出问题的节点，而不是从头再跑一遍完整链路。

## 面试官：如果生成结果不好，你怎么定位问题？

回答口径：

我会先看它属于哪类失败。

如果商品卖点不准，问题大概率在输入结构化或 Prompt 约束；如果画面风格不对，检查模板检索和风格标签；如果商品融合假，检查主体抠图、背景光源和融合参数；如果文字压住商品或越界，检查排版节点和安全区规则；如果合规没过，就检查规则库召回和文案生成。

所以项目里每个节点都会保存输入、输出、模型参数和质检结果，方便回放链路。

## 面试官：这个项目可以量化哪些指标？

回答口径：

可以从业务和技术两层看。

业务指标包括：单张图平均生成时间、人工改图次数、一次通过率、运营采纳率、A/B 图点击率或转化率。

技术指标包括：合规命中准确率、文字安全区通过率、商品主体分割质量、模板检索命中率、质检通过率、平均重试次数、单任务成本。

如果是上线试点，我会优先看“一次通过率、平均出图时间、人工修改次数、单任务成本”这四个指标。

## 面试官：如果让你继续优化，你会怎么做？

回答口径：

我会优先做三件事。

第一，增加品牌风格学习能力。把商家历史高点击素材沉淀成品牌风格向量，生成时优先贴近高转化风格。

第二，加强版式自动评估。除了规则判断安全区，还可以引入视觉模型评估文字可读性、视觉重心和主体突出度。

第三，接入真实投放反馈。把点击率、转化率、人工选择结果回流到模板库和 Prompt 策略里，让系统越用越懂业务。

## 30 秒项目总结

这个项目的核心价值不是简单调用文生图模型，而是把电商宣传图生产拆成一个可控的 Agent 工作流。系统通过卖点结构化、模板/RAG 检索、商品抠图、背景生成、文案排版、多尺寸适配和质检自愈，解决运营出图慢、合规风险高、品牌风格不稳定的问题。我的重点设计是结构化输出、合规双保险、资产复用和定向返工，让 AIGC 从“生成玩具”变成可以接近业务交付的工具。
